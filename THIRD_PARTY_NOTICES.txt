PlotTTY third-party notices

Releases are built with PyInstaller using PlotTTY.spec. On Windows, run
PlotTTY.exe and keep the app/ support directory beside it. Linux uses the same
folder layout with a PlotTTY executable; macOS uses a PlotTTY.app bundle.

PlotTTY's original code and icon are MIT licensed; see LICENSE.
Runtime dependencies are listed in requirements.txt:

  PySide6, Shiboken and Qt: https://doc.qt.io/qtforpython-6/licenses.html
  NumPy: https://github.com/numpy/numpy
  PyLink: https://github.com/square/pylink

The packaged Python runtime and bundled components retain their own notices.
PyInstaller's bootloader license is described in its distribution:
https://github.com/pyinstaller/pyinstaller/blob/develop/COPYING.txt

The release workflow does not generate VERSIONS.json, a consolidated licenses/
directory, or a corresponding-library-source ZIP. Before distributing a build,
inventory the bundled components and include their required license texts,
notices, and matching source distribution as applicable. See README.md.

Corresponding source and library replacement

When providing a corresponding-source archive alongside the application,
include the matching Qt/PySide/Shiboken sources, their upstream build
instructions, and PlotTTY's source and build recipe. Sources do not need to
be extracted to run PlotTTY.

You may modify or replace the LGPL libraries and reverse-engineer the application
to debug those modifications. Replace DLLs/extensions in their existing locations under app/
with builds compatible with the application's platform, Python and Qt versions.
No signature check prevents running with modified libraries. For changes needing
a rebuild, follow README.md in the application source, install the matching
dependency versions (substituting your rebuilt libraries), and run PyInstaller.
These instructions do not restrict any rights granted by the dependency licenses.
